## Task 1: Migrate acdefense-staging to Dashboard-Managed

**This is a Cloudflare dashboard action — no CLI, no code.**

The migration converts the locally-managed tunnel to a remotely-managed one. The token we already generated (`eyJhIjoiZWRiNGUw...`) stays valid. Zero downtime. **Irreversible** — but the right call since we want to manage ingress from the dashboard like the production tunnel.

- [ ] **Step 1: Open Cloudflare Zero Trust**

  Go to https://one.dash.cloudflare.com → Networks → Tunnels

- [ ] **Step 2: Locate acdefense-staging and click Migrate**

  Find `acdefense-staging` → click the `...` menu → **Migrate**. 
  
  Read the warning: "Any other configurations on the configuration file will not be migrated, and any changes you make locally will not be reflected on the dashboard." This is fine — we have no local config file. Click **Confirm**.

- [ ] **Step 3: Add Public Hostname for staging.acdefenseco.net**

  After migration, the tunnel moves to the "Configure" tab. Click **Configure** → **Public Hostnames** → **Add a public hostname**:

  | Field | Value |
  |-------|-------|
  | Subdomain | `staging` |
  | Domain | `acdefenseco.net` |
  | Service Type | `HTTP` |
  | URL | `website-staging:3000` |

  Save. CF automatically creates/updates the `staging.acdefenseco.net` CNAME record in the zone.

- [ ] **Step 4: Verify staging is reachable**

  ```bash
  curl -sI https://staging.acdefenseco.net | head -5
  ```

  Expected: `HTTP/2 200` or `HTTP/2 307` (redirect to login if NextAuth kicks in).

  If the container isn't responding, check it's healthy:
  ```bash
  ssh -i ~/.ssh/id_ed25519-doctl root@45.55.235.37 \
    "docker logs website-staging --tail 10"
  ```

## Task 3: Add CAA Records to acdefenseco.net

**acdefenseco.net has zero CAA records.** Since all TLS for this domain is served through Cloudflare's Universal SSL (Cloudflare acts as the TLS terminator), the only CA that should be allowed to issue certs is Cloudflare's own CA.

Adding these records costs nothing and prevents rogue cert issuance by other CAs.

**Option A — CF Dashboard:**

- [ ] **Step 1: Add CAA records in CF dashboard**

  Go to https://dash.cloudflare.com → `acdefenseco.net` → DNS → Add record for each:

  | Type | Name | Tag | CA domain | Flags |
  |------|------|-----|-----------|-------|
  | CAA | `acdefenseco.net` | `issue` | `cloudflare.com` | 0 |
  | CAA | `acdefenseco.net` | `issuewild` | `cloudflare.com` | 0 |
  | CAA | `acdefenseco.net` | `iodef` | `mailto:connect@josephjloss.com` | 0 |

**Option B — cfcli (if token is valid):**

- [ ] **Step 1: Add CAA records via cfcli**

  ```bash
  # cfcli doesn't natively support CAA type — use CF API directly
  # Get zone ID first (requires a valid token with zone:read)
  # Fallback: use dashboard (Option A above)
  ```

  Since cfcli doesn't support CAA record type natively, use the dashboard for this task.
